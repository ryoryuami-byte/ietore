# App Store Connect「プライバシー」の答え

App Store Connect → アプリのプライバシー で聞かれる項目と、その答えです。

---

## 結論

> **「このアプリではデータを収集しません」を選んでください。**
>
> App Store Connect の最初の質問
> 「このアプリまたはサードパーティのパートナーは、このアプリからデータを収集しますか？」
> に **「いいえ」** と答えると、以降の細かい質問はすべて省略されます。

## その答えでよい理由

Apple の言う「収集（collect）」は、
**データが端末から外へ出て、こちらや第三者が読める状態になること**を指します。
端末の中だけに保存され、外へ出ないものは「収集」に当たりません。

このアプリは、以下のいずれも行っていません。

| | |
| --- | --- |
| サーバーへの送信 | 無し。**通信そのものを一切行いません** |
| アカウント・ログイン | 無し |
| アクセス解析（Firebase / GA など） | 無し |
| 広告・広告SDK | 無し |
| クラッシュ報告サービス（Sentry など） | **無し。**（端末内に記録するだけ。下記参照） |
| サードパーティのSDK | 無し |

依存しているのは React と Capacitor のプラグイン（保存・ファイル・通知・画面スリープ・共有）だけで、
どれも端末の中で完結します。

## 確かめかた（申告する前に）

言葉だけでなく、実際に確かめられます。

1. 実機を**機内モードにして**、初回診断から記録・写真・引き継ぎまで一通り動かす
   → すべて動くはずです（通信を使っていないため）
2. Xcode の **Network** 計器を開いた状態でアプリを操作し、通信が出ないことを見る
3. コードを検索して、外部への通信が無いことを確かめる

```bash
grep -rnE "fetch\(|XMLHttpRequest|WebSocket|axios|https?://" src/ | grep -v "^src/legal.js"
```

`src/legal.js` に出てくる URL は、文面の中の文字列（お問い合わせ先など）だけです。

## クラッシュ報告について（判断の記録）

当初のロードマップには「クラッシュの監視を入れる（Sentry など）」と書いていました。
**これは入れないことにしました。**

Sentry のようなサービスは、落ちたときに端末の情報を外部サーバーへ送ります。
そうすると、

- プライバシーポリシーの「外部には送信されません」が**嘘になります**
- App Store のプライバシー申告が「データを収集します（診断情報）」に変わります
- このアプリのいちばん強い売りが1つ消えます

代わりに、**落ちた記録を端末の中だけに残す**形にしました（`src/crashLog.js`）。

- 最新5件まで。名前・体重・写真・メモは含めません
- 落ちた画面と、設定画面から、利用者が自分でコピーできます
- **送るかどうかを決めるのは利用者です。** こちらから取りにいくことはしません

そのぶん、こちらには不具合が自動では届きません。
**レビューと問い合わせを、発売直後は毎日見てください。** それが唯一の入口になります。

## 権限（iOS が出す許可ダイアログ）

| 権限 | いつ出るか | 説明文の場所 |
| --- | --- | --- |
| 写真ライブラリ | 「写真をえらぶ」を押したとき | `ios/App/App/Info.plist` の `NSPhotoLibraryUsageDescription` |
| カメラ | 同上（その場で撮る場合） | `NSCameraUsageDescription` |
| 通知 | **1回目をやりきった直後** | iOS が自動で出す |

いずれも、**その機能を使おうとした瞬間**にしか出しません。
起動直後にまとめて許可を求めると、断られやすく、審査でも指摘されます。

位置情報・連絡先・マイク・ヘルスケア（HealthKit）は**一切使っていません**。

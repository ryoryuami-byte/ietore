# 変更の記録

## v18.6.0（写真をカレンダーからも／月ごとに見くらべる）

### 写真の入り口を増やした

これまで写真を追加できるのは「記録」タブの、**今日ぶんだけ**だった。
撮り忘れた日をあとから埋める手段が無かった。

- カレンダーで日付をタップして開くシートに、写真の追加・削除を追加。
  過去の日にもさかのぼって入れられる（未来の日は、他の記録と同じく開けない）
- 保存先・削除・1日1枚・端末の外に出ないことは、これまでの写真とすべて同じ。
  入り口が増えただけで、しくみは何も変えていない

### 月ごとに見くらべる

「2枚をえらんで見くらべる」（1枚ずつ探す）とは別に、
「月ごとに見くらべる」を追加。‹ › で月そのものを行き来する。
写真がある月だけを飛び石で移動するので、空の月では止まらない。

その月に写真が2枚以上あるときは、小さな一覧からえらび直せる
（既定はその月でいちばん早い日に撮った1枚）。月ごとの計算は
`src/logic/photos.js` に切り出し、画面を持たない関数としてテストしてある。

### 写真の上限を 12 → 24 枚に

写真は v18.2 で localStorage の base64 から端末のファイルへ逃がしてあり
（`photoFiles.js`）、枚数は保存容量にほぼ効かなくなっている。
上限を上げられる状態になっていた（`RELEASE_ROADMAP.md` に前から書いてあった）ので、
月ごとの見くらべを2年ぶん意味のある長さで使えるよう、ここで上げた。

### 見つけて直したもの — ワークアウト中の「つぎへ」が押せないことがあった

写真の作業とは別に、下から出てくるシート・全画面の作りを触っていて見つけた。

**多くの端末の高さで、ワークアウト画面の「つぎへ」ボタンがタブバーの下に隠れて
押せなくなっていた。** タブバー（`TabBar`）は v18.3 で追加したときに z-20 で作ったが、
それより前からあった全画面の部品（ワークアウト画面・体感を聞くシート・
お休み申告シート・種目入れ替えのダイアログ・カレンダーの日づけシート）も
同じ z-20 のままだった。同じ z-index なら DOM で後にあるほうが勝つ、という
CSS の規則により、AppInner の中でいちばん最後に置かれているタブバーが、
これらの画面より**常に**上に描かれていた。

端末の高さによって隠れる／隠れないが変わるため、目視や偶然のタップでは
気づきにくい壊れかたをしていた。実際に Playwright で普通にクリックさせてみて見つけた。

- `SessionRunner`（ワークアウト画面）・`FeelingSheet`（体感を聞く）・
  `SkipSheet`（お休み申告）・`SwapDialog`（種目入れ替え）・`NoteSheet`
  （カレンダーの日づけシート）を、z-20 → z-30 に上げた。
  もともと z-30 だった `ConfirmSheet` / `PhotoCompare` / `WeekReview` /
  `CheerScreen` と同じ扱いにそろえただけで、レイアウトは変えていない
- **タブバーより下に隠れる全画面表示が無いことを、ソースから機械的に確かめるテストを追加**
  （`src/layers.test.js`）。同じ事故が二度と静かに起きないようにしてある

## v18.5.0（暗い部屋で使えるようにした）

このアプリは、夜に使われる。お知らせの初期値が20時なのがその証拠で、
「寝る前に、部屋を暗くして」がいちばん多い使われかたのはずだった。
そこに真っ白な画面を出していた。

- **ダークモード**（端末に合わせる／明るく／暗く）。
  選んだ瞬間に変わる。「端末に合わせる」なら、
  端末が夜モードに切り替わったときアプリも一緒に変わる
- **文字の大きさ**（ふつう／大きい／とても大きい）。
  床に寝ると画面は遠くなる。1.24倍まで大きくできる

### 色の持ちかたを変えた

v18.4 のときに「ダークモードは無理」と書いた。理由は
`Fig.jsx` が `fill={C.ink}` のように色を SVG の属性に直接書いていて、
属性は CSS の `var()` を解決しないからだった。作り直した。

- `C.ink` が返すのは `"#4A3242"` ではなく `"var(--c-ink)"` になった。
  実際の色は `tokens.js` の `PALETTE.light` / `PALETTE.dark` にあり、
  そこから CSS 変数を作って `<html>` に流し込む。
  テーマの切り替えは属性を1つ書き換えるだけで、React は何もしない
- 影・グラデーション・背景の点・幕も、色から計算してテーマごとに用意した。
  暗いテーマではカードの影が地に沈んで消えるので、
  代わりに髪の毛ほどの縁を1本引いて面の境目を出している
- SVG の線は `currentColor` か `style` に移した
- その場かぎりで書かれていた色（`"#E96A97"` など22か所）を
  トークンに寄せた（`pinkEdge` / `lavEdge` / `mintEdge` / `surfaceOk` / `disabled`）

### 見つけて直したもの

作りながら、テストと実際の画面が見つけたもの。

- **明るいテーマのコントラスト不足が2つ**。`pinkDeep` と `mintText` が、
  地のグラデーションのいちばん濃いところで 4.48 / 4.36 と AA を割っていた。
  出荷ずみの色である。両方わずかに濃くして通した
- **白文字を「文字の色」の上に載せていた4か所**。明るいテーマでは
  たまたま濃かったので読めていたが、暗いテーマでは色が反転して読めなくなる。
  白文字を載せてよい面（`pinkBtn` / 新設の `lavBtn`）に変えた
- **文字を大きくすると横にはみ出す**。Tailwind の `max-w-md` は rem なので、
  1.24倍で 555px になり 390px の画面に収まらない。
  さらに、列を指定していない `grid` は「いちばん折り返せない中身」まで
  列が広がるので、そこでも画面から出ていた。両方 CSS 側で直した
- **知らない診断の答えが、そのまま画面に出ていた**。
  引き継ぎの JSON に無い部位 id が入っていると
  「気になる部位のうち belly は…」のように id が出る。読み込み時に落とすようにした

### 目で見るための道具

```bash
npm run shots          # 明るい／暗いを5タブぶん撮る
npm run shots -- huge  # 文字を「とても大きい」にして撮る
```

テストは「色の比が 4.5 以上か」までしか見てくれない。
**「暗い画面で線が地に沈んでいないか」は、見ないと分からない。**
撮るついでに、横にはみ出していないかも数字で確かめている
（上の「はみ出し」は、この確認が見つけた）。

## v18.4.0（続けられなくなる場所を埋めた）

やめる人がやめる場所は、だいたい決まっている。
**「1日あいて連続が切れた日」と「今日のメニューがきつい／合わない日」**。
今回はそこだけを狙って埋めた。通信は増えていない。

### 連続が切れても、やめないようにする

- **連続日数の保護**。何も言わずに1日あけても、**ひと月に1度だけ**連続が切れない。
  保護を使ったことは黙っていない。ホームに「今月は1日ぶん、連続を守りました」と出す
- **節目のお祝い**。3・7・14・30・50・100・200・365日で、
  数字ではなく「何を成し遂げたか」を言葉にして出す
- **切れたあとの声かけ**。連続が0に戻っている人に、責めない文面を出す。
  何日あいたかで文面を変える（1〜2日／1週間以内／それ以上）
- **週の目標のリング**。日ごとに達成を追うより挫折しにくい。
  「診断どおり」のほか、週3〜6回から選べる

保護は**新しい保存データを増やしていない**。記録から毎回計算し直しているので、
引き継ぎファイルの形も変わらないし、数え方がずれることもない。

### 今日のメニューが合わないときに、逃げ道をつくる

- **1種目だけの差し替え**。種目の画面に「やさしく／別のもの／きつく」を追加。
  その日のメニュー全体を作り直さずに、1つだけ替えられる
- 替える先は、これまでどおりの決まりを全部守る。
  同じ流れ（①〜④）の中から選び、鍛える場所を変えず、
  避けたい部位・音の出る種目・腰への負担（1日1つまで）を外す
- 求めた向き（やさしく／きつく）に候補が無いときは、**黙って逆へ動かさない**。
  ボタン自体を出さない

### 前回と自己ベストを見せる

- 種目の画面に「前回」と「自己ベスト」を出す。
  更新した日は「自己ベスト更新です 🏆」を出す
- ここも**新しい保存データを増やしていない**。すでにある記録から読み出している

### 作りのほう

- `src/logic/streak.js`（連続・保護・節目）と `src/logic/history.js`（種目ごとの履歴）を追加
- `logic/plan.js` に `swapOne` / `hasSwap` を追加
- 設定画面の描画を `SettingGroup` に切り出した。
  新しい group を作ったときは、`<SettingGroup id="…">` を1つ置くだけでよい
- **settings.js に足したのに画面に出ていない設定を、テストで落とすようにした**。
  今回それを実際にやらかしたので、同じ取りこぼしが二度と通らないようにしてある
- テスト 190 → 191（`streak` 13件・`history` 15件・`swap` 12件を追加）
- 長期データのテストの時間上限をゆるめた。並列実行で CPU を取り合うと実測が数倍ぶれるため。
  ここで見たいのは桁が変わる劣化だけで、ミリ秒の上下ではない

## v18.1.0（動きながら使えるようにした）

運動している人は床にいて画面を見られない。ここが人気アプリと
いちばん差がついていたので、まとめて埋めた。通信は増えていない。

- **声で案内**。種目名・残り時間・左右の切り替え・休憩を読み上げる。
  端末に入っている音声を使うので、文字がどこかへ送られることはない
- **はじめる前のカウントダウン**（3、2、1、はじめ）
- **回数を数える**。テンポに合わせて数え、終わると1セット記録される
- **テンポ音**。「ゆっくり下ろす」を音で刻む。下ろす／上げるで高さを変えた
- 休憩の「とばす」「＋15秒」を追加
- 設定に「動きながら使う」を追加。声のオン・オフ、速さ、
  カウントダウン、回数を数える、テンポ音、1回にかける秒数を選べる

作りのほうの変更

- 設定の定義を `settings.js` に集約した。これまで初期値・検証・画面の
  3か所に散っていて、1つ忘れると「保存はされるが読み込むと消える」
  という壊れかたをしていた。**今後は1行足すだけで済む**
- 声かけの判断は `coach.js` に集約。画面側は設定を見なくてよい
- テスト30件を追加（設定の整合性、声かけの停止と後片づけ）

ここから先は **Mac と Apple Developer Program が要ります。**
コード側の準備は終わっているので、残りは登録・素材・審査です。

## 1. 連絡先を実在するものに差し替える ★必須

いまは `support@ietore.jp` という**仮のアドレス**が入っています。
プライバシーポリシーと利用規約の両方に出るので、必ず差し替えてください。

```bash
# src/legal.js の CONTACT を直してから
npm run legal      # docs/legal/*.md を作り直す
```

`src/legal.js` の 1か所を直すだけで、アプリの中と公開文書の両方が変わります。

---

## 2. プライバシーポリシーを公開する ★必須

**URL が無いと審査に出せません。** GitHub Pages がいちばん手軽です。

1. GitHub → このリポジトリ → Settings → Pages
2. Source を `Deploy from a branch`、ブランチを `main`、フォルダを `/docs` にする
3. 数分待つと `https://ryoryuami-byte.github.io/ietore/legal/privacy` で開けます

Markdown のまま公開されるので、見た目を整えたい場合は
HTML に変換するか、`docs/` に簡単な `index.html` を置いてください。

App Store Connect に登録するのは **プライバシーポリシーの URL** です。
サポート URL も必須なので、問い合わせ先を1行書いたページを同じ場所に置いてください。

---

## 3. 法務の文面を専門家に見てもらう ★必須

`src/legal.js` の文面は**素案**です。とくに次の3点は、書き方ひとつで意味が変わります。

- 免責の範囲（第4条）
- 準拠法・管轄（第8条）
- 未成年の扱い

健康・運動を扱うアプリなので、ここは省かないでください。

---

## 4. 版番号を合わせる

| 場所 | 値 |
| --- | --- |
| `package.json` の `version` | `18.0.0` |
| Xcode → App → General → Version（`MARKETING_VERSION`） | `18.0.0` |
| 同 Build（`CURRENT_PROJECT_VERSION`） | `1` |

`package.json` の値はビルド時にアプリへ埋め込まれ、
不具合の記録に「どの版で落ちたか」として残ります。**3か所を必ずそろえてください。**

> 初回リリースなのに 18 から始まるのは、
> 単一ファイルだったころの v17.2 から数えを続けているためです。
> 1.0.0 に戻したい場合は、上の3か所すべてを直してください。

## 5. アイコンとスプラッシュを差し替える

[../store/README.md](../store/README.md) のとおりに `assets/` へ置いてから:

```bash
npx capacitor-assets generate --ios --android \
  --iconBackgroundColor '#FFF3F7' --iconBackgroundColorDark '#FFF3F7' \
  --splashBackgroundColor '#FFF3F7' --splashBackgroundColorDark '#FFF3F7'
npm run sync
```

**いま入っているのは仮のアイコンです。** このまま提出しないでください。

## 6. TestFlight に上げて、モニターに配る

```bash
npm run ios        # ビルド → Xcode が開く
```

Xcode で Product → Archive → Distribute App → TestFlight。

**5〜10人に、少なくとも2週間**使ってもらってください。
見るべき数字と、実機のチェック表は [TESTING.md](TESTING.md) にあります。

ここを飛ばして審査に出すのは勧めません。
**自動テストでは絶対に分からないこと**（質問が多すぎて脱落する、通知が邪魔、
メニューがきつすぎる）が、ここでしか見つかりません。

### リジェクトされたら

**1回は返ってくるものと思って日程を組んでください。** 初回審査は1〜3日です。

多い指摘と、そのときの答えかた:

| 指摘 | 対応 |
| --- | --- |
| 「Webサイトを包んだだけでは」（4.2） | 通知・ファイル保存・共有・画面スリープ防止を使っていることを、画面の録画つきで説明する |
| 「健康情報の裏付けは」（1.4.1） | 医療的助言ではない旨を、起動時に必ず表示していることを伝える |
| 「プライバシーポリシーが開けない」 | URL がリダイレクトしていないか、日本以外からも見えるかを確認する |
| 「スクリーンショットが実際の画面と違う」 | 加工した文字を減らし、実画面に近いものに差し替える |

## 8. 発売

### 段階リリース（強く推奨）

App Store Connect → バージョンのリリース → **「段階的リリース」を選ぶ**

7日かけて 1% → 2% → 5% → 10% → 20% → 50% → 100% と広がります。
ひどい不具合が見つかったら、途中で止められます。
初回リリースこそ、ここを使ってください。

### 発売してからの2週間

**このアプリは不具合を自動で受け取りません**（外部にデータを送らないため）。
気づく手段はレビューと問い合わせだけです。

- [ ] **毎日**レビューを見る（App Store Connect → 評価とレビュー）
- [ ] 問い合わせメールを毎日見る
- [ ] レビューには返信する。特に低評価には必ず
- [ ] App Store Connect → 分析 で「継続率」を見る（1日後・7日後）

利用者から「落ちる」と言われたら、
**設定 → 不具合の記録 → 内容をコピー** を送ってもらってください。
版番号・日時・落ちた場所が入っています。

### 最初の更新（v18.0.1）

**バグ修正だけにして、素早く出してください。** 機能を足すのは、その次です。

## 9. Android（後追い）

土台はすでに用意してあります。iOS が落ち着いてから:

```bash
npm run android    # ビルド → Android Studio が開く
```

- Google Play Console の登録は **25USD（買い切り）**
- 通知の許可（`POST_NOTIFICATIONS` ほか）は `AndroidManifest.xml` に入れてあります
- **実機での確認が別途要ります。** iOS で通った項目でも、
  WebView の作りが違うので同じとは限りません
- Play は審査が数日かかることがあります（iOS より読めません）

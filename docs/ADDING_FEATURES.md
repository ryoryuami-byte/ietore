# 機能を足すときの手引き

この先も機能を足していく前提で、**足す場所を決めてあります**。
迷ったらここを見てください。

---

## 1. 設定（オン・オフ、選択肢）を足す

**`src/settings.js` の `SETTINGS` に1行足すだけです。**

初期値・読み込み時の検証・設定画面の表示は、すべてそこから自動で作られます。

```js
{
  id: "shakeToSkip", type: "toggle", def: false,
  group: "coach", label: "振ってスキップ",
  note: "端末を振ると次の種目へ進みます。",
},
```

| 項目 | 意味 |
| --- | --- |
| `id` | 保存されるときの名前。`core.shakeToSkip` で読めます |
| `type` | `toggle`／`choice`／`time`／`free` |
| `def` | 初期値。`choice` なら `options` の中の値であること |
| `group` | 設定画面のどのまとまりに出すか。`null` なら画面に出しません |
| `label` | 画面に出す名前 |
| `note` | 説明文（任意） |
| `options` | `choice` のとき `[[値, 表示], …]` |
| `dependsOn` | 別の設定がオフのとき、これも触れなくする |

**この方式にした理由。** 以前は設定を1つ足すのに3か所（初期値・検証・画面）を直す必要があり、
どれか1つ忘れると「保存はされるのに、読み込むと消える」という気づきにくい壊れかたをしていました。

新しい `group` を作った場合だけ、`src/screens/Settings.jsx` に見出しと
`<SettingGroup id="新しいgroup" core={core} onSet={onSet} />` を置いてください。
既存の `coach` と `keep` のコードをそのまま真似できます。

```jsx
<p style={{ color: C.muted }} className="text-xs mb-2 px-1">新しいまとまり</p>
<div style={card()} className="border-2 rounded-3xl px-5 py-5 mb-7">
  <SettingGroup id="新しいgroup" core={core} onSet={onSet} />
</div>
```

> テストが見張っています。`src/settings.test.js` が
> 「初期値が選択肢の中にあるか」「`DEFAULT_CORE` に入っているか」
> 「`dependsOn` の相手が実在するか」に加えて、
> **「`group` を持つ設定が、実際に設定画面から届くか」** を自動で確かめます。
>
> この最後の1つは、v18.4 で実際にやらかしたので足しました。
> `settings.js` に足しただけだと初期値も検証も付いてくるので動いた気になりますが、
> 画面に出し忘れると「保存はされるのに、誰も触れない設定」が静かにできあがります。

## 2. 声かけ・音を足す

**`src/coach.js` に関数を1つ足します。**

```js
function sayHalfway(core) {
  if (!on(core, "voiceOn")) return;
  speak("半分まで来ました");
}
```

役割分担はこうなっています。**この境目を守ってください。**

| ファイル | 知っていること | 知らないこと |
| --- | --- | --- |
| `speech.js` | 声の出しかた | いつ言うか |
| `sound.js` | 音の鳴らしかた | いつ鳴らすか |
| `coach.js` | **いつ、何を言う／鳴らすか**。設定も見る | 画面のこと |
| 画面 | 呼ぶタイミング | 設定・端末の対応可否 |

画面側は設定を見なくて構いません。
「設定がオフなら黙る」「端末が対応していなければ何もしない」は `coach.js` が引き受けます。

**時間のかかる声かけ（数える・カウントダウン）は、必ず「止める関数」を返してください。**
画面を閉じたあとも喋り続けるのが、いちばん困る壊れかたです。

```js
const stop = startRepCount(core, 10, onDone);
// 画面を離れるとき
stop();
```

## 3. 種目を足す

`src/exercises.js` の `EX` に足します。

```js
newExercise: {
  name: "種目の名前", fig: "squat", type: "reps", phase: "main", int: 2,
  focus: ["lower"], area: ["thighF"], stress: ["knee"],
  amount: { easy: 10, hard: 15 }, sets: { easy: 2, hard: 3 },
  tips: ["…"], ng: "…", adjust: "…",
},
```

気をつけること。

- `fig` は `components/Fig.jsx` にある絵の名前。無いと**スクワットの絵が出ます**
- `int`（強度）が 3 の種目は「ふつう」以上の人にしか出ません
- `noisy: true` を付けると、集合住宅を選んだ人には出ません
- `spineLoad: true` を付けると、1日1種目までになります
- `phase` は `warmup` / `main` / `cardio` / `cooldown` のどれか

足したら `npm test` を回してください。
`src/logic/plan.test.js` が **プロフィール288通り**で組み立てを試し、
「流れの順序が崩れていないか」「有酸素が毎日2種目か」などを確かめます。
`src/logic/swap.test.js` も同じ決まりを、1種目だけの差し替え（`swapOne`）について確かめます。
種目を足すと差し替え先の候補にも自動で入るので、こちらも一緒に通ることを見てください。

## 3.5 色を足す

`src/tokens.js` の `PALETTE` に、**明るい／暗いの両方**へ足します。
片方だけだと `tokens.test.js` が落ちます。

画面側では `C.あたらしい色` で使えます。中身は `"var(--c-あたらしい色)"` で、
実際の色は `<html data-theme>` によって切り替わります。

**気をつけること。**

- **SVG の属性に色を直接書かないこと。**
  `<circle stroke={C.pink}>` は効きません（属性は `var()` を解決しない）。
  `style={{ stroke: C.pink }}` か `currentColor` を使ってください。
  テストが見張っています
- **文字を載せる面は、`tokens.test.js` の表にも足してください。**
  「明るいほうは読めるが暗いほうは読めない」は、目では見つかりません
- **白文字を載せてよいのは `pinkBtn` と `lavBtn` だけです。**
  `pinkDeep` / `lavText` / `mintText` は「文字の色」で、
  暗いテーマでは明るくなります。背景に使うと白文字が消えます

足したら `npm run shots` で撮って見てください。

## 4. 画面を足す

- 大きい画面 … `src/screens/`
- 部品 … `src/components/`

`AppInner.jsx` が状態を持ち、画面へ渡しています。
新しいタブを足す場合は `components/TabBar.jsx` の `TABS` に1行足し、
`AppInner.jsx` の切り替えにその id を足してください。

**画面いっぱいのシート・ダイアログ（`fixed inset-0`）を足すときは `z-30` にしてください。**
下のタブバー（`TabBar`）は `z-20` で、`AppInner.jsx` の中でいちばん最後に
描かれています。同じ `z-20` にすると、CSS の規則（同じ z-index なら DOM で
後にあるほうが勝つ）でタブバーがシートの上に描かれ、**シートのいちばん下にある
ボタンがタブバーの下に隠れて押せなくなります**。端末の高さによって起きたり
起きなかったりするので、気づかれにくい壊れかたです（v18.6 で実際に、
ワークアウト画面の「つぎへ」がこれで押せなくなっていました）。

> `src/layers.test.js` が見張っています。`fixed inset-0` を含む要素に
> `z-20` 以下が付いていたら落とします。

`src/storage.js` の `DEFAULT_CORE` に足し、
`src/logic/validate.js` の `normalizeCore` に検証を足します

## 6. 足す前に確かめてほしいこと

### この機能は、通信を必要としますか？

必要なら、**入れる前に立ち止まってください。**

イエトレは「通信を一切行わない」を掲げています。これは
ストアの掲載文でも審査でも、いまいちばん強い売りです。
1つでも通信を足すと、

- プライバシーポリシーの「外部には送信されません」が嘘になります
- App Store のプライバシー申告が「データを収集します」に変わります
- 完全無料を続けにくくなります（サーバー代がかかるため）

判断の材料は [store/privacy-answers.md](../store/privacy-answers.md) にあります。

### アプリの容量を大きく増やしませんか？

動画や音声ファイルの同梱は、数十〜数百MBになります。
いまのアプリは1MB未満です。**ダウンロードをためらわせる大きさになっていないか**を見てください。

読み上げは端末の音声を使っているので、容量は増えていません。

### 「やることを増やす」機能になっていませんか？

このアプリの芯は、**考えることを減らすこと**です。
「今日は何をやろう」で止まる人のために、選択肢を1つに絞っています。

設定・入力欄・選ぶ場面を増やす機能は、その芯と逆を向きます。
足すなら、既定値のままでも成り立つ形にしてください。
